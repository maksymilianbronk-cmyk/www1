2.1Środowisko TIA Portal

S7-1200 programuje się wyłącznie w TIA Portal (Totally Integrated Automation). Wystarczy pakiet STEP 7 Basic (dodawany często do zestawów startowych); STEP 7 Professional potrzebny jest dopiero do S7-1500/300/400. Do wizualizacji HMI Basic Panels służy zintegrowane WinCC Basic.

  • Komputer łączy się z CPU zwykłym kablem Ethernet (port PROFINET). Domyślnie CPU nie ma adresu IP — TIA Portal znajduje go po MAC (funkcja „Accessible devices").
  • Typowa konwencja adresów: CPU 192.168.0.1, programator 192.168.0.241, maska 255.255.255.0.
  • Wersja firmware CPU (V4.x) musi zgadzać się z wersją wybraną w projekcie — sprawdzisz ją na tabliczce lub w „Online & diagnostics".

2.2Pierwszy projekt krok po kroku

  1. Create new project → nazwa i katalog.
  2. Add new device → Controllers → SIMATIC S7-1200 → CPU 1211C AC/DC/Rly → 6ES7211-1BE40-0XB0 → właściwa wersja firmware. (Możesz też wybrać „Unspecified CPU" i użyć detekcji sprzętu.)
  3. W Device configuration ustaw: adres IP (Properties → PROFINET interface), zachowanie po starcie (Startup → np. „Warm restart – RUN"), retentywność, bity zegarowe (patrz 2.7), filtry wejść.
  4. Uzupełnij PLC tags — nadaj nazwy wejściom/wyjściom (np. PrzyciskStart = %I0.0). Od tej pory programuj wyłącznie symbolicznie.
  5. Pisz program w Main [OB1] (i własnych blokach — patrz 2.4).
  6. Compile (ikona lub Ctrl+B) → Download to device → wybierz interfejs sieciowy → Load → Start CPU.
  7. Testuj w trybie Monitoring (okulary) — zielone linie = przepływ prądu w LAD.

2.3Jak CPU wykonuje program — cykl

Sterownik pracuje w nieskończonej pętli (typowo co 1–20 ms):

  1. Odczyt wejść fizycznych do obrazu procesu (obszar I),
  2. Wykonanie programu — OB1 od pierwszej do ostatniej sieci (network), wraz z wywołanymi blokami,
  3. Zapis obrazu wyjść (obszar Q) na wyjścia fizyczne,
  4. komunikacja, autodiagnostyka → i od nowa.
  • Konsekwencja nr 1: stan wejścia jest stały przez cały cykl — impulsy krótsze niż cykl gubią się (dlatego szybkie sygnały liczy sprzętowy HSC).
  • Konsekwencja nr 2: liczy się ostatni zapis do cewki w cyklu — nie steruj tą samą cewką z dwóch miejsc (błąd „podwójnej cewki").
  • Strażnik cyklu (watchdog) domyślnie 150 ms — przekroczenie wywołuje OB80 lub STOP. Nigdy nie używaj pętli oczekujących w programie.

2.4Bloki programowe: OB, FC, FB, DB

BlokNazwaDo czego służy
OBOrganization BlockPunkty wejścia wywoływane przez system operacyjny CPU: cykl główny (OB1), start (OB100), przerwania (czasowe, sprzętowe, błędów). Nie wywołujesz ich sam.
FCFunction (funkcja)Podprogram bez pamięci — dostaje parametry IN/OUT, zwraca wynik, niczego nie pamięta między wywołaniami. Idealny na obliczenia i logikę kombinacyjną.
FBFunction Block (blok funkcyjny)Podprogram z pamięcią — każde wywołanie ma własny DB instancyjny ze zmiennymi Static. Idealny na obiekty: napęd, zawór, sekwencja. Timery/liczniki IEC to też FB.
DBData BlockPamięć danych: globalny (dostępny zewsząd, np. „Receptura") lub instancyjny (należy do wywołania FB).
Dobra architektura małego programu OB1 tylko wywołuje bloki: FC_WejsciaSkalowanie → FB_Napęd (osobna instancja na każdy silnik) → FC_Alarmy → FC_Wyjścia. Dzięki temu ten sam FB obsłuży 1. i 10. silnik — zmienia się tylko DB instancyjny i podpięte zmienne.

Bloki „optymalizowane" (domyślnie) nie mają adresów bezwzględnych — dostęp tylko symboliczny, za to szybszy i bezpieczniejszy. Wyłącz optymalizację tylko, gdy komunikacja wymaga stałych offsetów (np. Modbus, PUT/GET).

2.6Języki programowania

LAD (Ladder) — schemat drabinkowy

Graficzny, wzorowany na schematach stycznikowych: szyna zasilająca, styki, cewki. Najlepszy do logiki załącz/wyłącz i najczytelniejszy dla utrzymania ruchu. W tym poradniku przykłady zapisujemy „tekstowo": --| |-- styk NO, --|/|-- styk NC, --( )-- cewka.

FBD — schemat bloków funkcyjnych

Ta sama logika co LAD, ale rysowana bramkami (AND/OR/=). Kwestia preferencji — konwersja LAD↔FBD jest w TIA Portal automatyczna.

SCL — Structured Control Language

Tekstowy język wysokiego poziomu (odmiana ST z IEC 61131-3, składnia pascalopodobna): IF, CASE, FOR, WHILE, REPEAT, wyrażenia arytmetyczne. Najlepszy do obliczeń, receptur, tablic i algorytmów. Przykład: 

IF #Start AND NOT #Awaria THEN
    #Silnik := TRUE;
ELSIF #Stop OR #Awaria THEN
    #Silnik := FALSE;
END_IF;

// pętla po recepturze
FOR #i := 1 TO 10 DO
    #Suma := #Suma + "Receptura".Skladnik[#i];
END_FOR;

S7-1200 nie obsługuje języków STL (AWL) ani GRAPH — te są zarezerwowane dla S7-1500/300/400. Sekwencje krokowe realizuje się w LAD/SCL wzorcem „step" (rozdział 4).

2.8Wgrywanie, tryb online i diagnostyka

  • Download: zmiany w blokach można wgrywać w RUN (bez zatrzymania maszyny), zmiany konfiguracji sprzętu wymagają STOP.
  • Monitoring (ikona okularów): podgląd na żywo stanów w kodzie; Watch table — podgląd i wymuszanie (modify) zmiennych; Force table — trwałe wymuszanie wejść/wyjść fizycznych (ostrożnie!).
  • Online & diagnostics: bufor diagnostyczny (przyczyny STOP), stan LED, ustawianie IP i czasu, reset do ustawień fabrycznych.
  • Diody CPU: RUN/STOP zielona = RUN, żółta = STOP; ERROR miga czerwono = błąd (szczegóły w buforze); MAINT = wymagana obsługa.
  • Kopia programu: karta pamięci SIMATIC MC (program transfer card) lub Upload z CPU (od V4 program da się wczytać z powrotem do projektu).
  • Zabezpieczenia: poziomy ochrony (read/write protection), know-how protect bloków, przywiązanie do numeru seryjnego karty/CPU.
